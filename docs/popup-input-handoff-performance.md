# Popup 首次建窗与输入窗口交接

2026-11-20，KUI-VIS-065。延续064，仅使用POCO F2 Pro（31936bb6/API36）独立R8与motion包，核心停止、空配置、竖屏、字号1.0、玻璃默认关闭；原版Flutter只作为本地源码参考，本组不启动或修改原版。

## 实现及来源

- Popup首次定位在测量阶段更新位置。原实现又在组合阶段读取该坐标构造背景偏移，并向卡片栈传入未使用的位置参数；改为在绘制阶段读取偏移，移除未使用参数，保留原坐标/安全区/锚点算法。固定Flutter布局包装也保留稳定child，本组不改变菜单排版。
- ScrollState首次未测量时maxValue为Int.MAX_VALUE。把它区分为未知，而非可滚动，避免短菜单先误启滚动再回退；仍订阅真实上限，让长菜单保持滚动和拖选互斥。
- 原回源动画完成后同批次调用action并移除Popup；现在注册实际View detach回调，先移除旧窗口，再检查外部展开/生命周期并执行选择动作。取消等待不执行旧动作；源按钮在移窗前恢复。没有增加固定delay或隐藏预热窗口。
- 链接表单的显示、隐藏、清焦统一归属Dialog内控制器。窗口获焦后只请求TextField焦点，由其建立输入连接；移除紧接requestFocus的显式show。提交、失败、返回从同一Dialog清焦/收键盘，等待窗口焦点期间读取最新忙态。

固定Flutter手机链接表单为SnapSheetRoute，URL/批量字段autofocus；并非Material AlertDialog。Kotlin本组保留现有居中表单和菜单450/500ms曲线，不将此优化记为手机Flutter完整布局等价。NTP输入框局部控制器仅作生命周期参考，未搬用其自绘遮罩/窗口动画禁用逻辑。

## 测量方式

使用063/064独立`.performance`变体：完整R8/release库、非debuggable、无Instrumentation宿主，基线为ac8c1195。每轮冷进程，5轮来源菜单→链接表单→收IME→退表单，加工具四Tab共25阶段。perf与截图/录屏/Instrumentation分开；所有安装按明确session完成后串行执行。

Perfetto追加wm/input事件，按FrameTimeline layer区分宿主、Popup及后创建的Dialog，再以token匹配同进程UI/RenderThread。Dialog首段包括首次布局及IME入场；线程切片是进程帧工作，不是该窗口独占CPU。表单销毁后gfx窗口缺席仍记不可观测，不能把宿主零帧当关闭免费。

本机附件`../acceptance-artifacts/popup-ime-poco-20261120/`保留APK/安装回拉、原始gfx、trace、SQL/CSV、单测/Lint/UI回执及失败批次。

## 原始失败

- baseline1被首次安装通知权限弹窗挡住，未进入菜单测量；仅授予独立测试包通知权限后新目录重跑。
- candidate1构建漏LocalFocusManager导入；candidate2测试误引用未依赖的UiDevice，改现有Instrumentation发送系统Back。
- final5补最新忙态保护时漏rememberUpdatedState导入；补导入后最终重建。

## 最终构建与交互结果

最终build-final6：App627本批执行，Service220/Core39/Common34任务内复用，共920项JVM结果零失败/错误/跳过；performance-R8、motion/Test、未签名Release-R8构建通过。motion Lint为0错误/75警告/15提示，Release为0错误/71警告/14提示；MLKit三个注册器DEX门禁通过。651份源码摘要与最终两类包快照一致，三个独立APK安装回拉匹配。

POCO最终同套motion包22/22：新增5项真实窗口/IME交接，液滴菜单5项、配置表单5项、age2项、主菜单2项，以及几何/阴影/配置视觉各1项。输入前先核对自然焦点和真实窗口IME；单条/批量切换、重开草稿、失败重试、防重复提交、系统Back先收键盘再退表单、前后台恢复和动作发生时旧Popup已经detach均通过。初始URL仅模拟扫码后的表单入口，不是重新验收摄像扫码；草稿范围为同会话返回/重开，不是冷进程持久化。中间5/5及6/6不累计到最终22项。

38张组件图经4张拼图目视，35张具名图与063比较，其中20张固定几何帧、2张阴影和5张配置稳态图共27张像素一致；其余8张液滴采样图不同，目视正常，不称像素一致。最终R8来源菜单/表单已目视；独立自然录像实际5.369秒/159原PTS帧，8fps抽样显示回源、表单、IME入场/收起和返回，没有观察到整屏异常闪烁。抽样不是逐帧验收，录像不参与性能计量。`steady-visual.json`误以063深色稳态图对照本轮浅色图，原结果保留并标为不可比较，不作为回归证据。

## R8性能与取舍

每个gfx目录均包含5轮菜单流程，下面是进程卡顿帧/总帧。`remote-open`同时包含菜单回源、Dialog及IME，不是Dialog独立掉帧数。

| 批次 | 来源菜单打开 | 回源→表单→IME |
| --- | ---: | ---: |
| 旧包baseline2 | 14/171 | 21/289 |
| 旧包反向baseline3 | 14/172 | 23/296 |
| 未拆窗candidate1 | 14/172 | 20/288 |
| detach1 | 15/172 | 21/295 |
| detach2 | 14/174 | 19/289 |
| 最终final1 | 15/170 | 20/292 |

最终两段合计35/462（7.58%），旧包为35/460（7.61%）和37/468（7.91%），**未证明整体掉帧率稳定下降**。收IME阶段均0卡顿；表单关闭后窗口已销毁，仅剩宿主少量帧，不据此称关闭无成本。

六份Perfetto均无正值error/data_loss统计；按窗口及同进程token匹配。下表UI为首帧`Choreographer#doFrame`包容墙钟耗时，不是CPU、单窗口独占时间或完整点击到可输入时间。

| trace批次 | Popup首帧UI/ms | Dialog首帧UI/ms | 点击分发结束→Dialog首帧开始/ms |
| --- | ---: | ---: | ---: |
| baseline1 | 74.566 | 87.226 | 565.123 |
| baseline2反向旧包 | 69.404 | 93.009 | 549.112 |
| candidate未拆窗 | 74.040 | 82.837 | 551.109 |
| detach1 | 72.963 | 71.836 | 583.388 |
| detach2 | 74.401 | 71.350 | 573.954 |
| final | 75.327 | 69.291 | 583.880 |

拆开窗口后，Dialog首帧主线程切片减少约18～24ms，两个中间detach批次也呈现相同方向；对应首帧UI调度运行时间从71.050/73.565ms降至57.089ms。这支持局部交接负担下降，仍不足以归因到某个Compose/原生函数。代价是Dialog开始绘制晚了18.757～34.768ms；保留了原500ms回源动画，不能宣称整个弹框响应更快。Popup首帧最终75.327ms，未稳定改善。

当前以真实detach代替同批次拆窗建窗，主要明确窗口所有权和取消时序；不通过固定延迟或隐藏窗口预热换取局部数字。RenderThread首帧切片虽有变化，缺完整原生函数/GPU fence证据，不能称慢帧归因已闭环。
