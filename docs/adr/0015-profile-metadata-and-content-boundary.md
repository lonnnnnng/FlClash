# 配置元数据与文件内容分离

状态：accepted

KClash 将配置的可查询元数据放在 Room，将实际 YAML 内容放在应用自己的配置文件目录。Room 记录来源类型、名称、订阅地址、更新时间、自动更新和订阅用量等字段；更新时先写临时文件，成功替换后再更新元数据。配置删除同时删除数据库记录和对应文件。

这个边界让列表、当前配置选择和订阅更新不需要把大段 YAML 放进数据库，也保留了 Mihomo 后续按文件读取和校验的路径。代价是数据库事务无法回滚已经完成的文件系统操作，因此写入顺序必须保持“临时文件完成后才提交元数据”，并在失败时清理临时文件。

本地 YAML 导入时，KClash 读取系统文档选择器返回的内容并复制到自己的配置目录，只把配置元数据写入 Room，不保存外部 URI 权限。这样外部文件位置变化不会影响已经导入的配置，也让远程订阅、本地文件和自定义配置最终都遵循同一份核心输入文件边界。
