# 网络观察由应用进程持有

状态：accepted

日期：2026-11-05

`NetworkObserver` 在 `KClashApplication.onCreate()` 中、按需连接和运行恢复之前启动。它负责把底层网络与 DNS 的变化交给 Mihomo，随应用进程存续；`ProxyService` 和 `VpnService` 不再拥有它的注册/注销生命周期。此顺序与本地 Flutter 上游在 `quickSetup` 前启动网络观察一致。

停止态的配置加载、Provider 更新、进程恢复及下一次启动都需要系统 DNS。把观察器放在前台服务模块中，会使配置先加载、观察器后注册，也会让某个服务销毁时清空另一条使用路径所需的共享网络信息。因此，停止服务只释放服务自己的资源，不能注销共用观察器或清空 DNS；真实网络变化继续由 Connectivity callback、DNS 合并任务和网络连接重置处理。进程退出后系统回收该进程注册的回调。

核心启停、配置应用和系统恢复仍由唯一 `CoreRuntimeManager` 串行处理。本决策不增加第二个核心启动入口，不改变 Go 保护回调或 TUN 初始化顺序。只读网络快照和 socket 保护计数用于区分失败阶段，不记录端点，也不把回调计数视为完整连接保护证明。

代价是应用停止核心后仍接收底层网络变化；这是维持停止态网络能力的有意行为。注册失败仍保留原有错误记录，`started=false`，不伪造成功。模式切换真机回归确认配置加载前已注册，纯代理→VPN→纯代理→停止后注册时间保持且 DNS 有效。

`system-vpn-dns-recovery-redmi-20261105.json` 记录最终两轮默认冷启动与 SIGKILL 恢复首个 TUN HTTPS 成功，以及此前冷首请求的间歇失败。该证据支持生命周期修正和本轮实网结果，尚不能证明节点 DNS/拨号失败的唯一根因或全部 Always-on 稳定性。
