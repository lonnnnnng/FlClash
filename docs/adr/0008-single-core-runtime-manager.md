# 使用单一核心运行管理器协调 Android 服务

状态：accepted

在 `service` 模块建立唯一的核心运行管理器，统一负责 Go Mihomo 的 start/stop/restart、配置切换、崩溃恢复、前台通知和运行状态；`VpnService` 只负责 TUN，`ProxyService` 只负责本地代理模式，二者通过管理器协作且不各自启动核心。UI 通过命令接口请求状态变化，不直接操作 Service 或 gomobile。

这个边界保持核心生命周期只有一个事实来源，避免页面、VPN 服务和代理服务之间互相覆盖状态；代价是所有启动和停止请求都必须经过管理器的状态机和序列化队列。

## 2026-11-02：VPN 与本地代理模式

VPN 启用选择独立于 Profile 保存，默认开启。关闭时管理器只启动 ProxyService 和核心监听，不申请 VPN 授权、不创建 TUN。开启时先由 Activity 检查系统授权，再由管理器等待平台服务确认。ProxyService 也发布启动结果，不能只凭启动 Intent 把核心标为运行。

运行中修改选择只保存下一次的模式，保留当前会话；卡片区分保存值与已应用值，提供“重启生效”。显式重启共用同一把生命周期锁，停止后等待两个服务实例退出，再启动新模式。保存失败保持原值，启动失败撤销服务启动并清空应用态，不显示虚假的连接成功。
