# Provider 正文冷进程恢复缺口

- 编号：KUI-009。
- 基线：`4ede6b850b9d019b8f98ccc8ae2884ccbb2f7c29`。
- 归属：Kotlin 正文编辑器持久化与导航，不是 Mihomo 缺陷；Flutter 只读参考。
- 当前状态：本组已验，802项JVM/统一构建/双Lint通过；Redmi九场景首次恢复9/9、再次恢复3/3、相邻回归10/10。

## 原因与上游参考

原 `ProfileStatisticsViewModel` 的正文只存在 ViewModel 内存，`provider-picker` 仅保存系统选择器的目标与摘要；Activity 重建成功不能证明进程死亡后正文可恢复。原 `KClashApp` 的配置详情 ID 只存在系统保存树，没有独立正文恢复后的导航入口。

先检查 Flutter `lib/views/proxies/providers.dart` 的 `_sideLoadProvider`、`_EditProviderViewState._handleSave/_handlePop`：失败保留编辑器，成功返回，离开要求保存确认。没有可直接移植的 Android 进程死亡恢复契约。Kotlin 保留这些交互，补独立持久化，不合并 Flutter 提交。

## 实现与约束

`ProviderDocumentDraft` 保存配置 ID、名称、原 recoveryKey/digest/正文、当前正文、提交意图和独立 UI 保存树，不序列化核心绑定。`provider-document.v1` 使用既有 Keystore AES-GCM、noBackup 与 AtomicFile，和文件选择器分文件；R8 保留快照字段。

恢复先等待正式配置读取，只重开同一当前配置的详情，不切换用户选择。管理器重新核对当前配置与输入，并建立新核心绑定：正文等于已落盘意图时只确认，仍为原 digest 时保留草稿等待显式重试，其他版本或目标删除保留冲突草稿。恢复不自动调用侧载。保存意图写盘失败禁止正式提交，已提交但回读失败只允许重新确认。

正文无法重新绑定时仍可查看输入、返回确认放弃。加密读取失败保留原密文；独立保存树保存选区/滚动/确认框，不进入系统 Bundle。关闭与迟到持久化共用互斥和代次，重试读取也受代次保护；停止宿主不接收旧输入拆除回调。

删除边界补充：引用源未变时，丢失的派生缓存可以由正式投影逻辑重建，源正文保持；引用源的 Room 行或文件缺失时，不允许用遗留缓存顶替，草稿保留并拒绝保存。冷启动缓存缺失用例由外部驱动在旧 PID 消失后核对并删除本例准确路径；源删除两类再做第二次冷启动，避免把同进程恢复误记为持久恢复。
