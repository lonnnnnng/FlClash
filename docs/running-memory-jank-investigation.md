## 本轮实现

对照固定Flutter连接组件的按需轮询（`connections_table.dart`中的`pollsConnections`及`getConnectionCount`分支），Kotlin完整活动连接列表改为只有应用前台且“网络活动→活动连接”Tab可见时才读取。首页仍每秒读取轻量流量/累计/连接计数，最近请求、DNS与日志事件保持原链路。离开Tab或退后台取消在途请求，回到Tab立即刷新；进程会话变化清空旧连接列表。取消检查位于Manager结果之后，避免其`runCatching`捕获取消后把旧结果写回界面。

空列表一旦成功加载，后续刷新也不再每秒切到loading。网络错误仍保留旧列表和受控错误，下一次成功清除；详情继续保存点击时的单条快照，不依赖当前列表重新查找。

源文件：`ui/MainViewModel.kt`、`ui/KClashApp.kt`；回归位于`MainViewModelTelemetryTest`。本组没有修改核心、节点路由或配置正文。

## 同态内存协议与边界

使用同一份工作区原`1.yaml`的精确设备副本，原文件不修改；真实系统选择器分别导入。输入34220字节，6代理、34组、93条主规则、92个HTTP Rule Provider；不打印节点凭据或订阅链接。原版已有两份远程配置保留，测试只新增`kclash-064-1.yaml`，结束恢复此前选择和VPN开关并删除测试项。

一次只运行一个核心；分别比较纯代理与VPN、首页前台和按HOME后台。首页使用深色、竖屏、字号1.0；两版mips/MTU9000/cubic/系统代理/IPv6关闭/DNS劫持关闭/绕过私有路由保持相同，独立Kotlin VPN测试临时打开allowBypass以匹配原版，非产品默认改动。模式RULE、没有手动改变组选择；自动健康检查可能选择不同叶节点，未冻结逐节点状态。每种状态静置30秒，再五次间隔5秒采样；采样时不运行录屏、Perfetto、Instrumentation或测速。

原版运行后的`dumpsys meminfo`、`--local`、`-s`、`-a --package`均只有头部，系统自身可读取其他应用与Kotlin。`smaps_rollup`被拒绝，未提权或绕过。因此**跨应用统一比较`/proc/PID/status`的VmRSS/RssAnon/RssFile/RssShmem**，不把Kotlin的PSS除以原版的RSS。逐PID读表前后核对进程身份，含包名前缀子进程；PSS缺失保持null。RSS含共享驻留页，不等于独占物理内存；不把各状态混成一个总体倍数。

同源输入和页面/运行参数并不保证缓存完全相同：已安装原版0.9.3、Kotlin0.1.10开发源码及内核/Geo版本不同，已有Provider缓存与实际网络背景流量也可能不同。本组为同设备、同源文件、同运行模式和页面的产品实测，不是相同内核二进制/相同缓存字节的控制实验；不外推其他大配置或长期运行。
