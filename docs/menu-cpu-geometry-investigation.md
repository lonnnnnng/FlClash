# KUI-027：菜单线程计数与几何候选

2026-11-09，基线 `2f2479b7`。**未保留产品优化，菜单首开/关闭仍未闭环**。保留分阶段测量工具、CPU诊断入口、固定动效帧门禁以及失败候选，避免把重复计算减少直接当作性能改善。

## 测量修正

新驱动直接复用 `tool/android_menu_frame_report.py`，按每个 Window 自己的重置时刻筛选，首次打开与两次复开分别报告。新增普通帧覆盖比例、Vsync延后、同步队列等待和完成经过时间；失效时间戳拒绝，不补零。关闭后 Popup 消失仍为不可观测。原历史 `result.json` 混窗数字不改，以后续分窗报告为准。

独立未混淆 motion 包通过 `/proc/self/task/<tid>/schedstat` 读自身线程的累计CPU、就绪队列等待和运行次数，字段依据 [Linux文档](https://docs.kernel.org/scheduler/sched-stats.html)。本Redmi可读，不需要root或改变SELinux。多条同名 RenderThread 按TID/startTicks分开，死亡/倒退/缺字段拒绝；计划100ms采样，实际读时刻/开销和输入注入起止原样保留。

基线三个关闭窗口主线程CPU为350.426/305.465/297.324ms，最活跃且持续存活的同一 RenderThread 为250.520/235.982/231.836ms，其就绪队列等待10.493/8.591/11.628ms。诊断包窗口中确有CPU消耗，不能全部解释为调度排队。它不提供原生栈、GPU时间或Popup独占归因，也不能作为正式R8成绩。首次基线open的同步输入阻塞使第一观察点在230ms，不能称覆盖首100ms。
